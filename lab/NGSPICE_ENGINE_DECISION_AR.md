# قرار محرك المحاكاة — ISLAM LAB

## القرار
اعتماد حزمة `eecircuit-engine` كمرشح المحرك الأولي لتكامل ngspice داخل المتصفح، بدلاً من نسخ تطبيق WebSpice كاملاً.

## أدلة التحقق
- المستودع الرسمي للحزمة: https://github.com/eelab-dev/EEcircuit-engine
- ترخيص المستودع: MIT، وملف LICENSE موجود في الجذر.
- إصدار الحزمة وقت التقييم: 1.9.0، منشور على npm.
- واجهة الاستخدام الموثقة: `new Simulation()`, ثم `await start()`, ثم `setNetList(text)`, ثم `await runSim()`.
- نتائج المحاكاة تعاد كبيانات متغيرات وقيم رقمية، ويمكن استخراج معلومات التشغيل عبر `getInfo()` و`getError()`.
- محرك الحزمة يضم ngspice WASM ويستخدم نظام ملفات افتراضياً داخلياً؛ يجب التأكد من تحميل ملف WASM محلياً بعد البناء وعدم الاعتماد على CDN وقت التشغيل.

## قرار الترخيص
- حزمة EEcircuit-engine: MIT بحسب LICENSE الرسمي.
- ngspice: ترخيص أساسي BSD-3-Clause مع مكونات فرعية ذات تراخيص مختلفة؛ يجب الاحتفاظ بإشعارات التراخيص المرفقة وعدم حذف ملفات COPYING أو إشعارات النماذج.
- لا ننسخ WebSpice source حالياً: README يذكر MIT لكن GitHub API لم يُظهر ملف LICENSE في جذر ذلك المستودع، لذا لا نعتمد كوده قبل توضيح الترخيص.

## معمارية ISLAM LAB
- تشغيل المحرك داخل Web Worker منفصل.
- تمرير netlist نصياً فقط من الواجهة إلى العامل.
- إرجاع أسماء المتغيرات والبيانات الرقمية، لا كائنات المحرك.
- عدم السماح بتحميل ملفات خارجية أو تنفيذ أوامر نظام.
- الاحتفاظ بكل ملفات المحرك محلياً ضمن حزمة البناء؛ لا CDN ولا مفاتيح API ولا حساب مطلوب.

## اختبار القبول الإلزامي
1. بناء الموقع بنجاح.
2. تهيئة المحرك دون أخطاء WASM.
3. تشغيل دائرة RLC مرجعية.
4. التحقق من وجود متغير الزمن وجهد الملف/العقدة وعدد نقاط أكبر من صفر.
5. مقارنة الجهد/التيار مع حل تحليلي مستقل ضمن سماحية معلنة.
6. اختبار إعادة التشغيل مرتين داخل نفس العامل، ثم اختبار إعادة تحميل الصفحة دون اتصال.

## الحالة
قرار اختيار أولي موثق، وليس إعلاناً عن نجاح التكامل. لا تُعرض حالة المحاكاة للمستخدم على أنها جاهزة قبل اجتياز جميع اختبارات القبول.
