# محرك المجال ثلاثي الأبعاد DD — النواة المرجعية

## الهدف
طبقة حساب مستقلة عن نموذج Elmer المحوري الحالي. تستقبل مسارات TX وRX ثلاثية الأبعاد من CAD أو من هندسة ملف مقاسة، وتحسب المجال المغناطيسي بقانون Biot–Savart والمحاثة المتبادلة الموقعة بتكامل Neumann.

## لماذا هذه الخطوة
ملف DD32 ذو جناحين، وليس ملفاً دائرياً محورياً. نموذج Elmer الحالي مفيد كمرجع محوري مستقل، لكنه لا يصف جناحي DD أو منطقة التداخل. هذه النواة لا تستبدل Elmer؛ إنها طبقة تحقق هندسي أولى قبل بناء نموذج FEM ثلاثي الأبعاد.

## صيغة الهندسة
ملف JSON يتضمن:
- paths_m.TX وpaths_m.RX: رؤوس مسار لفة واحدة بإحداثيات X/Y/Z بالمتر.
- turns.TX وturns.RX: عدد اللفات المعتمد.
- observation_points_m: نقاط حساب المجال.
- tx_current_a: تيار المقارنة.

يجب أن يكون كل مسار مغلقاً. اتجاه ترتيب النقاط يحدد القطبية.

## الاختبار والتشغيل
من هذا المجلد:
```bash
python3 -m unittest -v test_filament_model.py
python3 run_dd3d_reference.py dd32_geometry.json --output dd32_reference.json
```

يقارن الاختبار مجال الحلقة الدائرية العددي بالحل التحليلي على محورها، ويفحص تقارب الخطأ، وخطية المجال مع التيار واللفات، وتماثل المحاثة المتبادلة، وانعكاس القطبية.

## القيود العلمية
- الأسلاك خطوط مركزية رفيعة؛ لا يوجد نموذج لمقطع النحاس أو توزيع التيار داخله.
- التكامل العددي بنقاط منتصف المقاطع؛ يجب اختبار التقارب لكل هندسة فعلية.
- لا يوجد بعد هدف موصل أو تربة أو نبضة زمنية أو دائرة TX أو AFE أو ضوضاء.
- لا تستخرج هذه النواة عمق كشف أو SNR أو احتمال كشف.
- لا تسمى الهندسة DD32 قبل تصدير مسارات اللف الفعلية بعد تثبيت القالب وقياس التداخل والارتفاع والفصل.

## بوابة الانتقال
1. توفير مسارات TX/RX من CAD أو قياسات قالب DD32.
2. إثبات تقارب المجال والمحاثة المتبادلة بزيادة عدد مقاطع المسار.
3. مقارنة هندسة بسيطة مع حل FEM مستقل.
4. ثم إضافة هدف موصل وزمن متغير، فالتربة، فدائرة الاستقبال.
