# قرار وحدة التحكم — ISLAM NEXTGEN

التاريخ: 2026-11-14
الحالة: اختيار معماري محدد، بانتظار إغلاق BOM والتوريد.

## 1. القرار

**لا نفترض أن لدى المستخدم أي لوحة معالج جاهزة.** حزمة التحكم التي يجب توفيرها للجهاز الجديد هي:

1. **NUCLEO-G474RE / STM32G474RE** — وحدة النبضات والقياس والحماية والتوقيت.
2. **ESP32-S3 N16R8 DevKitC-1** — Wi-Fi وWebServer وجسر تحديث Firmware.
3. **Android ISLAM DETECTOR** — واجهة التحكم والتسجيل.

هذه ليست ثلاث وحدات متنافسة؛ لكل واحدة وظيفة منفصلة. لا نستخدم ESP32-S3 كـADC PI رئيسي ولا نعتمد على الهاتف لتوقيت النبضة.

## 2. لماذا STM32G474RE؟

- Cortex-M4 حتى170MHz.
- HRTIM لتوليد توقيت TX وSWb وADC triggers عتادياً.
- ADC1 وADC2 يدعمان regular simultaneous mode مع DMA.
- مقارنات COMP وDAC داخليان يتيحان current trip وrecovery event دون polling.
- ST-LINK مدمج في NUCLEO-G474RE لتطوير Firmware واسترداد اللوحة.

اللوحة الرسمية تحمل STM32G474RE LQFP64، وتوفر Arduino/Morpho connectors. خريطة الأرجل المعتمدة موجودة في `hardware/ISLAM_NEXTGEN_CONTROLLER_PINMAP_AR.md`.

## 3. لماذا ESP32-S3 منفصل؟

- Wi-Fi AP وWebServer واتصال Android.
- نقل الإعدادات والبيانات من/إلى STM32.
- تخزين Firmware مؤقتاً والتحقق من SHA-256.
- تنفيذ بروتوكول ROM bootloader عبر USART3 بعد انتقال STM32 الآمن إلى System Memory.

هذا الفصل يمنع انقطاع Wi-Fi أو ضغط التطبيق من تغيير توقيت النبضة أو تعطيل الحماية.

## 4. الربط المعتمد مبدئياً

- STM32 PB10 / USART3_TX → ESP32 GPIO18 / UART1_RX.
- STM32 PB11 / USART3_RX ← ESP32 GPIO17 / UART1_TX.
- 3.3V TTL مع GND مشترك وحماية ESD ومقاومات سلسلة.
- STM32 PB8/BOOT0 وNRST ليسا جزءاً من التحديث الاعتيادي؛ تحديث الهاتف يستخدم jump-to-system-memory من Firmware سليم. recovery عند تلف Firmware يحتاج تهيئة option bytes/JP7 أو ST-LINK.
- تغذية 5V للمنطق واللوحات، و12V مستقلة لمرحلة TX، مع rails تناظرية منفصلة للـAFE.

## 5. حالة التوفر والشراء

- NUCLEO-G474RE: ST تصنفه Active. صفحة ST تعرض الشراء المباشر، لكن لم يظهر مخزون موزعين مؤكد داخل الجزائر. TME/DigiKey يعرضان مخزوناً دولياً، لكن الشحن والجمارك للجزائر غير مؤكدين.
- ESP32-S3 N16R8: ظهرت عروض محلية، وأفضلها لوحة مع headers ملحومة مسبقاً من TIKNO؛ يلزم تأكيد المخزون قبل الدفع.
- لا نشتري STM32F303 Discovery كبديل لمجرد توفره محلياً؛ لا يطابق معمارية HRTIM/ADC المختارة ولا نحتاج منصة اختبار وسيطة إضافية.

## 6. حدود الاعتماد

- اختيار المتحكم المعماري: **محسوم مبدئياً — STM32G474RE**.
- اختيار جسر Wi-Fi: **محسوم مبدئياً — ESP32-S3 N16R8**.
- اللوحات المرجعية لا تعني أن الجهاز النهائي سيحتويها دائماً؛ بعد إثبات الدارة قد ندمج STM32G474 في PCB رئيسية مجمعة مصنعياً، مع إبقاء وحدة Wi-Fi plug-in إذا كان ذلك أفضل للصيانة.
- لا شراء حتى اكتمال schematic وBOM وتأكيد قنوات التوريد؛ لا نفترض امتلاك المستخدم لأي معالج أو لوحة.
