# ISLAM FREE AGENT — تطبيق المدير المساعد

## حالة النسخة الحالية

هذه وحدة Android مستقلة باسم الحزمة `com.islamfreeagent.app`، منفصلة عن:
- `app`: تطبيق ISLAM DETECTOR للاتصال بوحدة ESP32-S3.
- `lab`: تطبيق ISLAM LAB للمحاكاة والتحليل الهندسي.

النسخة التجريبية `0.1.1` تقدم:
- واجهة عربية RTL.
- قائمة مهام محلية يمكن إضافتها وتعليمها كمكتملة وحذفها.
- حفظ المهام داخل مساحة التطبيق على الهاتف واسترجاعها بعد إغلاق التطبيق.
- تعطيل Android Auto Backup لعدم نسخ قائمة المهام إلى حسابات النسخ الاحتياطي.
- حد أقصى 500 مهمة و180 حرفاً لعنوان المهمة لمنع تضخم التخزين المحلي.
- تجاهل بيانات JSON التالفة كقائمة فارغة؛ لا تتحول البيانات التالفة إلى مهام قابلة للتنفيذ.
- لا تحتاج إلى اتصال بالإنترنت ولا تطلب أذونات شبكة.

## حدود صريحة

هذه ليست بعد نسخة المدير الذكي المتصل بمحرك Python أو Ollama. لا تنفذ فحوصات GitHub، ولا تشغل المحاكاة، ولا تنشئ اقتراحات هندسية. ولا يوجد بعد اتصال Android بمحرك Ollama أو دورة اقتراح وموافقة فعلية من الهاتف. شاشة الحالة توضح أن محرك Ollama غير مربوط. لا يجوز وصف هذه النسخة بأنها وكيل مستقل أو مساعد ذكاء اصطناعي مكتمل.

## البناء والتحقق

من جذر المستودع:

```bash
gradle --no-daemon :agent:testDebugUnitTest :agent:assembleDebug
```

الناتج المتوقع:

`agent/build/outputs/apk/debug/agent-debug.apk`

يجب اعتبار APK صالحاً للتجربة فقط بعد نجاح اختبارات الوحدة، وفحص الحزمة، والتثبيت والتشغيل الفعلي على هاتف Android. بناء Debug لا يمثل إصداراً نهائياً موقعاً.

## جسر الحالة المحلي — المرحلة الأولى

أضيف `tools/islam_agent/bridge_health.py` لتوفير `GET /v1/health` على `127.0.0.1` فقط. يفحص وجود واجهة Ollama المحلية دون كشف أسماء النماذج. لا يقبل عمليات تعديل، ويرفض طلبات المتصفح ذات Origin، ولا يفتح منفذاً على شبكة LAN. تشغيله: `python3 tools/islam_agent/bridge_health.py`.

هذه مرحلة صحة محلية فقط؛ لا يوجد TLS أو اقتران هاتف أو واجهات مهام/اقتراحات بعد. لذلك لا يتصل تطبيق Android بهذا الخادم حالياً.

## ربط الهاتف بمحرك المدير المساعد

عقد الربط الآمن بين تطبيق Android ومحرك Python/Ollama المحلي موثق في `docs/agent/ANDROID_AGENT_BRIDGE_API_AR.md`. هذا العقد مواصفة فقط؛ خادم الاتصال وTLS والاقتران وعميل Android لم تُنفذ بعد. لا تفتح Ollama على الشبكة ولا تستخدم HTTP مكشوفاً.

## شروط إعلان الجاهزية الفعلية

لا تُعلن النسخة جاهزة للعمل الفعلي قبل اجتياز جميع البنود التالية:

1. نجاح اختبارات Android وبناء APK والتحقق من اسم الحزمة وبصمة SHA-256.
2. تثبيت APK وتشغيله على هاتف Android فعلي، وفحص حفظ المهام بعد إغلاق التطبيق وإعادة تشغيل الهاتف.
3. تنفيذ جسر Python بخدمة HTTPS، وبصمة شهادة مثبتة، ورمز اقتران أحادي الاستخدام، ورمز جلسة محفوظ في Android Keystore.
4. تنفيذ عميل Android واختبارات رفض الشهادة الخاطئة والجلسة المنتهية والطلبات غير المصرح بها.
5. ربط حالة Ollama والمهام والاقتراحات دون فتح منفذ Ollama على الشبكة.
6. عرض الاقتراح وخطواته وادعاءاته في الهاتف، وطلب موافقة بشرية مستقلة قبل أي تنفيذ.
7. اختبار الرفض والخطة المعدلة والاقتراح القديم وانقطاع الاتصال وإعادة التشغيل، والتأكد من عدم تكرار التنفيذ.
8. اختبار دورة كاملة على حاسوب مضيف وهاتف فعليين وتوثيق النتائج.

## المرحلة التالية

1. اختبار APK على هاتف حقيقي والتحقق من حفظ المهام بعد إعادة تشغيل التطبيق.
2. تصميم عقد اتصال آمن مع خدمة المدير المساعد، دون تخزين GitHub tokens داخل APK.
3. ربط تقارير التدقيق وحالة المهام بالواجهة مع إبقاء الموافقة البشرية قبل أي تنفيذ.
4. إضافة سجل قرارات وتقارير قابلة للتصدير.
5. اختبار اتصال Ollama على جهاز محلي فعلي قبل إعلان توفر التوليد الذكي.
