# ISLAM FREE AGENT — تطبيق المدير المساعد

## حالة الإصدار

الإصدار الجاري: `0.3.0`  
اسم الحزمة: `com.islamfreeagent.app`

هذا التطبيق مستقل عن:
- `app`: تطبيق ISLAM DETECTOR المتصل بوحدة ESP32-S3.
- `lab`: تطبيق ISLAM LAB للمحاكاة والتحليل الهندسي.

## ما يعمل في التطبيق

- واجهة عربية RTL.
- مهام محلية: إضافة، إكمال، إعادة فتح، وحذف.
- حفظ المهام في مساحة التطبيق، بحد أقصى 500 مهمة و180 حرفاً للمهمة.
- تعطيل Android Auto Backup لبيانات المهام.
- تجاهل JSON المحلي التالف بأمان.
- عميل HTTPS يثبت بصمة شهادة الخادم SHA-256، ويرفض عناوين المضيف العامة.
- اقتران برمز لمرة واحدة، ثم تخزين رمز الجلسة مشفراً بمفتاح Android Keystore.
- عرض حالة محرك Ollama، وقراءة مهام المشروع من الحاسوب.
- طلب اقتراح من Ollama وعرض تفاصيله وخطواته ونقاط التحقق.
- رفض الاقتراح أو الموافقة عليه بعد إدخال عبارة التأكيد الحرفية.
- لا يقبل التطبيق أوامر shell أو مسارات حرة أو رموز GitHub.

## محرك الكمبيوتر والجسر الآمن

المحرك Python ويستعمل Ollama المحلي. يبقى Ollama مربوطاً بـ`127.0.0.1:11434` على الحاسوب، ولا يتصل به الهاتف مباشرة.

الجسر الجديد:
- `tools/islam_agent/bridge_server.py`: خادم HTTPS على عنوان IPv4 خاص بالشبكة المحلية فقط.
- `tools/islam_agent/run_bridge.py`: ينشئ شهادة TLS ذات SAN مطابق لعنوان الكمبيوتر، ويعرض بصمتها ورمز اقتران عشوائياً صالحاً لخمس دقائق.
- `GET /v1/health`: حالة الجسر وOllama.
- `POST /v1/pair`: اقتران أحادي الاستخدام وإصدار رمز جلسة.
- `GET /v1/tasks`: قراءة مهام المشروع.
- `POST /v1/proposals`: طلب اقتراح واحد من المنسق وOllama.
- `GET /v1/proposals/pending`: مراجعة الاقتراح المعلق.
- `POST /v1/proposals/{id}/decision`: رفض أو موافقة صريحة.

توجد حدود لحجم الطلبات، وعدد محاولات الاقتران، ومعدل الطلبات. رمز الجلسة يبقى في ذاكرة الخادم فقط ويُبطل عند إيقافه أو إعادة تشغيله. المفتاح الخاص لشهادة TLS يُحفظ خارج المستودع في مجلد المستخدم `.islam-free-agent/bridge-tls`.

### تشغيل الجسر على الكمبيوتر

المتطلبات:
1. Python 3.
2. Ollama مثبت ويعمل، مع نموذج موجود فعلياً.
3. OpenSSL متاح في PATH.
4. الكمبيوتر والهاتف على شبكة Wi-Fi المحلية نفسها.

اعرض أسماء النماذج المثبتة على الكمبيوتر:

```bash
ollama list
```

ثم افتح الطرفية في جذر المستودع وشغّل الجسر مع اسم نموذج موجود عندك:

```bash
python tools/islam_agent/run_bridge.py --model "اسم-النموذج-المثبت"
```

سيعرض البرنامج:
- عنوان HTTPS المحلي، مثل `https://192.168.1.5:8765`.
- بصمة شهادة SHA-256.
- رمز اقتران مؤقت من ستة أرقام.

لا تغلق نافذة الجسر أثناء الاتصال. لا تفتح المنفذ على الإنترنت أو الراوتر، ولا تفتح منفذ Ollama للشبكة. إذا منع جدار حماية الكمبيوتر الاتصال، اسمح بالمنفذ 8765 على الشبكة الخاصة فقط.

### الاقتران من الهاتف

1. ثبّت APK الإصدار 0.2.0.
2. أدخل عنوان IPv4 الظاهر في الطرفية والمنفذ 8765.
3. أدخل بصمة SHA-256 كاملة كما ظهرت، دون تغيير.
4. أدخل رمز الاقتران المؤقت واضغط «اقتران الهاتف بالكمبيوتر».
5. افحص حالة المحرك، ثم اعرض مهام المشروع.
6. اطلب اقتراحاً؛ اقرأ المهمة والخطوات والادعاءات.
7. للرفض اضغط «رفض الاقتراح». للموافقة اكتب العبارة الظاهرة حرفياً ثم اضغط «موافقة وتنفيذ».

عند إيقاف الجسر أو إعادة تشغيله، تنتهي جلسة الهاتف ويجب الاقتران من جديد. لا تشارك رمز الاقتران أو بصمة شهادة قديمة مع جهاز آخر.

## حدود التنفيذ الحالية

النموذج لا ينفذ أوامر حرة. بوابة السياسة تسمح فقط بقراءة ملفات محددة أو تشغيل مجموعة اختبارات وكيل ثابتة، مع checkpoint لمنع تكرار الخطوات المكتملة. لا توجد في هذا الإصدار صلاحية كتابة ملفات المصدر أو الاتصال بـGitHub أو الدمج أو تغيير إعدادات الجهاز.

نجاح اختبارات الكود وبناء APK لا يثبت وحده أن Ollama يعمل على حاسوب المستخدم أو أن الهاتف والحاسوب قد اجتازا اختبار اتصال ميدانياً. يلزم اختبار فعلي على هاتف Android وحاسوب متصلين بالشبكة نفسها قبل وصف النظام بأنه مجرّب ميدانياً.

## البناء والتحقق

```bash
gradle --no-daemon :agent:testDebugUnitTest :agent:assembleDebug
```

الناتج:

`agent/build/outputs/apk/debug/agent-debug.apk`

يجب أن يجتاز الملف اختبارات Android، والتحقق من اسم الحزمة، وفحص ZIP، وبصمة SHA-256. ملفات Debug للتجربة وليست إصداراً نهائياً موقعاً للنشر التجاري.

## اختبارات القبول قبل إعلان الجاهزية النهائية

1. نجاح اختبارات Python وAndroid على آخر commit.
2. نجاح TLS pinning مع الشهادة الصحيحة ورفض الشهادة الخاطئة.
3. رفض رمز اقتران منتهي أو مستعمل أو محاولات تخمين متكررة.
4. رفض جلسة غير صالحة وطلبات خارج حدود المعدل والحجم.
5. اختبار الهاتف والحاسوب فعلياً على شبكة خاصة.
6. التأكد من أن Ollama لا يستمع إلا على loopback.
7. إنشاء اقتراح فعلي من نموذج مثبت، ثم رفضه دون تنفيذ.
8. الموافقة على خطة مسموحة، والتحقق من نتائجها وتحديث حالة المهمة.
9. اختبار فشل خطوة، والاستئناف دون تكرار الخطوات المكتملة.
10. توثيق اختبار تثبيت وتشغيل على هاتف Android فعلي.

## ربط GitHub المجاني من الهاتف — الإصدار التجريبي التالي

تظهر داخل التطبيق لوحة «ربط GitHub — مجاني» للاتصال المباشر بـGitHub REST API من Android عبر HTTPS.

### إنشاء رمز محدود الصلاحيات
1. افتح GitHub من المتصفح ثم Settings → Developer settings → Personal access tokens → Fine-grained tokens.
2. أنشئ رمزاً جديداً وحدد المستودع الوحيد `Khaledserdani/IslamDetector`.
3. حدد صلاحيات القراءة فقط: Metadata: Read، Contents: Read، Actions: Read، Pull requests: Read.
4. ضع تاريخ انتهاء مناسباً، ثم انسخ الرمز إلى لوحة التطبيق. لا ترسله في المحادثات ولا تحفظه في ملفات المشروع.

### ما تعرضه اللوحة
- التحقق من هوية حساب GitHub.
- اسم المستودع والفرع الافتراضي وحالته خاص/عام.
- الفروع المتاحة.
- طلبات الدمج المفتوحة.
- آخر خمس عمليات GitHub Actions وحالاتها.
- حفظ الرمز مشفراً بـAES-GCM مع مفتاح Android Keystore، مع زر لفصل الربط وحذف الرمز من الهاتف.

### حدود الأمان والمجانية
- لا يوجد خادم وسيط ولا اشتراك مدفوع؛ الاتصال من الهاتف مباشرة إلى `api.github.com`.
- هذه المرحلة قراءة فقط؛ لا تطلب صلاحية كتابة الملفات أو الدمج أو إدارة الحساب.
- لا تضع الرمز في السجلات أو Git أو APK أو ملفات إعدادات المشروع.
- GitHub Actions مجاني ضمن الحصة المجانية المقررة للحساب والمستودع؛ قد تُطبق حدود استخدام GitHub المجانية. لا نفعّل خدمات مدفوعة ولا نطلب ترقية.
- إذا انتهت صلاحية الرمز أو سُحب، أنشئ رمزاً جديداً محدوداً وأعد الربط.
