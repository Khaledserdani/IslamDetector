# ISLAM FREE AGENT — تطبيق المدير المساعد

## حالة الإصدار

الإصدار الجاري: `0.5.0`  
اسم الحزمة: `com.islamfreeagent.app`

هذا التطبيق مستقل عن:
- `app`: تطبيق ISLAM DETECTOR المتصل بوحدة ESP32-S3.
- `lab`: تطبيق ISLAM LAB للمحاكاة والتحليل الهندسي.

## ما يعمل في التطبيق

- واجهة عربية RTL.
- مهام محلية: إضافة، إكمال، إعادة فتح، وحذف.
- حفظ المهام في مساحة التطبيق، بحد أقصى 500 مهمة و180 حرفاً للمهمة.
- تعطيل Android Auto Backup لبيانات المهام.
- تجاهل JSON المحلي التالف بأمان.
- عميل HTTPS يثبت بصمة شهادة الخادم SHA-256، ويرفض عناوين المضيف العامة.
- اقتران برمز لمرة واحدة، ثم تخزين رمز الجلسة مشفراً بمفتاح Android Keystore.
- عرض حالة محرك Ollama، وقراءة مهام المشروع من الحاسوب.
- طلب اقتراح من Ollama وعرض تفاصيله وخطواته ونقاط التحقق.
- رفض الاقتراح أو الموافقة عليه بعد إدخال عبارة التأكيد الحرفية.
- لا يقبل التطبيق أوامر shell أو مسارات حرة أو رموز GitHub.

## محرك الكمبيوتر والجسر الآمن

المحرك Python ويستعمل Ollama المحلي. يبقى Ollama مربوطاً بـ`127.0.0.1:11434` على الحاسوب، ولا يتصل به الهاتف مباشرة.

الجسر الجديد:
- `tools/islam_agent/bridge_server.py`: خادم HTTPS على عنوان IPv4 خاص بالشبكة المحلية فقط.
- `tools/islam_agent/run_bridge.py`: ينشئ شهادة TLS ذات SAN مطابق لعنوان الكمبيوتر، ويعرض بصمتها ورمز اقتران عشوائياً صالحاً لخمس دقائق.
- `GET /v1/health`: حالة الجسر وOllama.
- `POST /v1/pair`: اقتران أحادي الاستخدام وإصدار رمز جلسة.
- `GET /v1/tasks`: قراءة مهام المشروع.
- `POST /v1/proposals`: طلب اقتراح واحد من المنسق وOllama.
- `GET /v1/proposals/pending`: مراجعة الاقتراح المعلق.
- `POST /v1/proposals/{id}/decision`: رفض أو موافقة صريحة.

توجد حدود لحجم الطلبات، وعدد محاولات الاقتران، ومعدل الطلبات. رمز الجلسة يبقى في ذاكرة الخادم فقط ويُبطل عند إيقافه أو إعادة تشغيله. المفتاح الخاص لشهادة TLS يُحفظ خارج المستودع في مجلد المستخدم `.islam-free-agent/bridge-tls`.

### تشغيل الجسر على الكمبيوتر

المتطلبات:
1. Python 3.
2. Ollama مثبت ويعمل، مع نموذج موجود فعلياً.
3. OpenSSL متاح في PATH.
4. الكمبيوتر والهاتف على شبكة Wi-Fi المحلية نفسها.

اعرض أسماء النماذج المثبتة على الكمبيوتر:

```bash
ollama list
```

ثم افتح الطرفية في جذر المستودع وشغّل الجسر مع اسم نموذج موجود عندك:

```bash
python tools/islam_agent/run_bridge.py --model "اسم-النموذج-المثبت"
```

سيعرض البرنامج:
- عنوان HTTPS المحلي، مثل `https://192.168.1.5:8765`.
- بصمة شهادة SHA-256.
- رمز اقتران مؤقت من ستة أرقام.

لا تغلق نافذة الجسر أثناء الاتصال. لا تفتح المنفذ على الإنترنت أو الراوتر، ولا تفتح منفذ Ollama للشبكة. إذا منع جدار حماية الكمبيوتر الاتصال، اسمح بالمنفذ 8765 على الشبكة الخاصة فقط.

### العمل التلقائي والنافذة الليلية

يبدأ الجسر افتراضياً نافذة عمل يومية من **20:00 مساءً إلى 06:00 صباحاً بتوقيت الجزائر**، ويفحص كل 5 دقائق داخلها:
- يدعم المجدول عبور منتصف الليل، ويوقف العامل عند 06:00 ويعيد تشغيله عند 20:00.
- إذا ولّد Ollama اقتراحاً يتكوّن حصراً من محاكاة DC أو RLC أو AC المعتمدة، يشغّلها المدير تلقائياً دون انتظار موافقة؛ لأنها عمليات حسابية لا تتحكم بأي جهاز مادي ولا تعدّل ملفات المشروع.
- يتحقق من المؤشرات العددية ويحفظ مدخلات الدارة والنتائج في `artifacts/agent/lab_runs/`.
- إذا احتوى الاقتراح على كتابة ملف أو تعديل مصدر أو عملية خارج المحاكاة المختبرية، يبقى الاقتراح معلقاً لمراجعتك. لا يكتب المدير المصدر ولا يرفع تغييرات GitHub تلقائياً.
- إذا كان هناك اقتراح ينتظر مراجعتك أو رفع GitHub سابق، يتوقف العامل عن بدء مهمة جديدة حتى تُحسم المراجعة أو عملية الرفع.
- حالة العامل وآخر نتيجة ونافذة العمل تظهر عند الضغط على «فحص حالة المحرك».

يمكن إيقاف المتابعة الدورية مع إبقاء الجسر متاحاً:
```bash
python tools/islam_agent/run_bridge.py --model "اسم-النموذج-المثبت" --no-continuous
```

يمكن تغيير الفاصل، والحد الأدنى 300 ثانية:
```bash
python tools/islam_agent/run_bridge.py --model "اسم-النموذج-المثبت" --interval-seconds 600
```

يمكن تغيير ساعات العمل:
```bash
python tools/islam_agent/run_bridge.py --model "اسم-النموذج-المثبت" --work-start 19:00 --work-end 05:00
```

هذه متابعة مستمرة ما دام الكمبيوتر والجسر وOllama يعملون؛ ليست خدمة سحابية تعمل بعد إطفاء الكمبيوتر.

### الاقتران من الهاتف

1. ثبّت APK الإصدار 0.5.0.
2. أدخل عنوان IPv4 الظاهر في الطرفية والمنفذ 8765.
3. أدخل بصمة SHA-256 كاملة كما ظهرت، دون تغيير.
4. أدخل رمز الاقتران المؤقت واضغط «اقتران الهاتف بالكمبيوتر».
5. افحص حالة المحرك، ثم اعرض مهام المشروع.
6. اطلب اقتراحاً؛ اقرأ المهمة والخطوات والادعاءات.
7. للرفض اضغط «رفض الاقتراح». للموافقة اكتب العبارة الظاهرة حرفياً ثم اضغط «موافقة وتنفيذ».

عند إيقاف الجسر أو إعادة تشغيله، تنتهي جلسة الهاتف ويجب الاقتران من جديد. لا تشارك رمز الاقتران أو بصمة شهادة قديمة مع جهاز آخر.

## تنفيذ التعديلات بأمان — الإصدار 0.4.2

أضيفت قدرة كتابة محلية محدودة إلى محرك الكمبيوتر:
- يقترح Ollama تعديلاً على شكل بيانات JSON فقط؛ لا ينفذ تعليمات حرة.
- عند كتابة ملف، يتضمن الاقتراح المسار المسموح والمحتوى الكامل للملف.
- يعرض تطبيق Android المحتوى الكامل قبل الموافقة.
- لا يبدأ التنفيذ إلا بعد إدخال عبارة التأكيد الحرفية.
- الكتابة ذرية، وتقتصر على قائمة مسارات ثابتة في سياسة الوكيل.
- لا يمكن للوكيل حذف الملفات أو تعديل الأسرار أو رموز GitHub أو ملفات Actions أو سياسة الأمان أو منفذ الأدوات.
- كل خطوة ناجحة تُحفظ في checkpoint. إذا فشل الاختبار، تتوقف الخطة ويمكن إعادة المحاولة دون تكرار الخطوات المكتملة.
- تعديلات Java تتطلب `android_unit_tests` (Gradle + Android SDK)، وتعديلات Python تتطلب `agent_unit_tests`؛ ترفض السياسة خطة الكتابة إذا غاب اختبار النوع المناسب.
- يرسل الجسر ردوداً محدودة الحجم ويظل Ollama على loopback.

### الملفات التي يمكن تعديلها في هذه المرحلة

- `tools/islam_agent/local_agent.py`
- `tools/islam_agent/orchestrator.py`
- `tools/islam_agent/agent_cycle.py`
- `docs/agent/ISLAM_FREE_AGENT_EXECUTION_AR.md`
- `docs/agent/agent_worklog.md`

القائمة ثابتة داخل `agent_policy.py`، ولا يستطيع النموذج توسيعها بنفسه. ملفات Android الكبيرة وعميل GitHub والجسر وملفات السياسة ومنفذ الأدوات تبقى للقراءة فقط في هذه المرحلة؛ لن نسمح باستبدالها بملف جزئي.

### حدود مهمة يجب عدم إخفائها

- ينفذ الجسر الكتابة المحلية والاختبارات على الكمبيوتر أولاً؛ بعد نجاحها يرفع التطبيق المحتوى المعتمد عبر GitHub Contents API إلى الفرع `feature/islam-free-agent-safe-write` وينشئ commit هناك.
- لا يكتب التطبيق إلى `main` أو الفرع الافتراضي، ولا ينفذ merge. المحاكاة المختبرية الحسابية المسموحة فقط تعمل تلقائياً؛ كل كتابة مصدر أو تغيير مشروع يتطلب موافقتك، والرفع لا يبدأ قبل نجاح الاختبارات المحلية.
- يجب أن يبقى الكمبيوتر والجسر وOllama يعملون أثناء التنفيذ. إغلاق الجسر يوقف استقبال أوامر الهاتف، لكن ملفات checkpoint تبقى للاستئناف عند تشغيله مجدداً.
- لا توجد صلاحية تحكم مادي تلقائي أو كتابة مصدر غير مراقبة. الاستقلالية التلقائية محصورة في محاكاة DC/RLC/AC الحسابية المسموحة وتسجيل نتائجها؛ تشغيلها يتوقف عند نهاية النافذة أو إيقاف الجسر.
- لا تُعتبر المهمة مكتملة إلا بعد نجاح كل الاختبارات المحددة.

## ربط GitHub المجاني من الهاتف — الإصدار التجريبي التالي

تظهر داخل التطبيق لوحة «ربط GitHub — مجاني» للاتصال المباشر بـGitHub REST API من Android عبر HTTPS، ورفع الملفات المعتمدة إلى فرع العمل بعد نجاح الاختبارات.

### إنشاء رمز محدود الصلاحيات
1. افتح GitHub من المتصفح ثم Settings → Developer settings → Personal access tokens → Fine-grained tokens.
2. أنشئ رمزاً جديداً وحدد المستودع الوحيد `Khaledserdani/IslamDetector`.
3. حدد الصلاحيات: Metadata: Read، Contents: Read and write، Actions: Read، Pull requests: Read. الكتابة مطلوبة فقط لرفع التعديلات المعتمدة إلى فرع العمل المحدد.
4. ضع تاريخ انتهاء مناسباً، ثم انسخ الرمز إلى لوحة التطبيق. لا ترسله في المحادثات ولا تحفظه في ملفات المشروع.

### ما تعرضه اللوحة
- التحقق من هوية حساب GitHub.
- اسم المستودع والفرع الافتراضي وحالته خاص/عام.
- الفروع المتاحة.
- طلبات الدمج المفتوحة.
- آخر خمس عمليات GitHub Actions وحالاتها.
- حفظ الرمز مشفراً بـAES-GCM مع مفتاح Android Keystore، مع زر لفصل الربط وحذف الرمز من الهاتف.

### حدود الأمان والمجانية
- لا يوجد خادم وسيط ولا اشتراك مدفوع؛ الاتصال من الهاتف مباشرة إلى `api.github.com`.
- صلاحية الكتابة محصورة في Contents للمستودع الواحد، ويستخدمها التطبيق لرفع ملفات القائمة المسموحة إلى فرع العمل فقط. لا يطلب صلاحية إدارة الحساب أو الدمج.
- لا تضع الرمز في السجلات أو Git أو APK أو ملفات إعدادات المشروع.
- GitHub Actions مجاني ضمن الحصة المجانية المقررة للحساب والمستودع؛ قد تُطبق حدود استخدام GitHub المجانية. لا نفعّل خدمات مدفوعة ولا نطلب ترقية.
- إذا انتهت صلاحية الرمز أو سُحب، أنشئ رمزاً جديداً محدوداً وأعد الربط.
