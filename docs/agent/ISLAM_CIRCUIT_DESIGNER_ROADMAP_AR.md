# خارطة المصمّم الهندسي الاحترافي للدوائر – ISLAM

## القرار الهندسي
الهدف ليس إضافة قائمة أسماء مكونات إلى مولّد SVG، بل بناء سلسلة تصميم إلكتروني موحدة تعتمد على مواصفة دائرة canonical circuit model، ومنها تُشتق الرموز والتوصيلات وملفات التصنيع والمحاكاة والفحوص. لا يُسمح بإنشاء مخطط أو BOM أو netlist كل واحد بصورة مستقلة حتى لا تتناقض المخرجات.

## البنية المستهدفة
1. **محلل المتطلبات:** يحول وصف المستخدم إلى متطلبات قابلة للقياس: الوظيفة، جهد/تيار التغذية، الحمل، الإشارات، الدقة، السرعة، الحرارة، البيئة، القيود الميكانيكية والكلفة والتوافر.
2. **مكتبة المكونات:** بيانات موثقة للمكونات والرموز والأرجل والوظائف الكهربائية والحزم والحدود والتفاوتات والبدائل والمصادر والنماذج.
3. **نموذج الدارة الموحد:** عقد وشبكات ومكونات متعددة الأرجل ووحدات IC متعددة الأقسام وموصلات وتسميات طاقة وأرضي وروابط بين الصفحات.
4. **محرّك قواعد التصميم الكهربائي ERC:** فحص الأرجل، أنواعها، اتجاهات الإشارات، تعدد مخارج القيادة، الأرجل العائمة، التغذية، الأرضي، حدود الجهد والتيار، القطبية، الحماية، التوصيل والقدرة والتبريد.
5. **مخطط احترافي:** تصدير مشروع KiCad أصلي قابل للفتح والتعديل، لا صورة SVG فقط؛ مع رموز صحيحة وأرقام أرجل وأسلاك وعقد وعناوين وكتل صفحات ومرجع كل عنصر.
6. **محرك المحاكاة:** تكامل محلي مع ngspice للتحليلات الملائمة: نقطة التشغيل وDC sweep وAC وTransient والضوضاء والحساسية وغيرها ضمن دعم المحرك والنموذج. نماذج الشركات لا تُعتبر متاحة لمجرد وجود اسمها؛ يلزم مصدر ملف النموذج وفحصه ومطابقة ترتيب الأرجل.
7. **فحوص مستقلة:** مقارنة اتصالات KiCad مع netlist، اختبارات مرجعية تحليلية، تحقق وحدات وأبعاد، فحص حدود التشغيل، تحليل أسوأ حالة وتفاوتات وMonte Carlo عند توفر النموذج.
8. **BOM وملفات التنفيذ:** رقم القطعة والشركة والحزمة والكمية والتصنيف والبدائل والمصدر، ثم لاحقاً PCB والـGerber وملفات التجميع عندما يكتمل محرك اللوحات.
9. **تقرير هندسي:** الافتراضات، الحسابات، مصادر البيانات، نماذج المحاكاة، مجال الصلاحية، المخاطر، التحذيرات، وقرار الحالة: Draft / Prototype / Validated / Build-Ready.

## مجالات الدارات المطلوب دعمها
- الدارات التناظرية: مضخمات، مرشحات، مذبذبات، مقارنات، قياس واستشعار.
- الدارات الرقمية: البوابات والمنطق التتابعي والساعات والواجهات.
- مصادر الطاقة: خطية وتبديلية، Buck/Boost/Flyback، شحن وحماية البطاريات.
- دوائر القدرة: MOSFET/BJT/IGBT، قيادة البوابات، المحركات، الأحمال الحثية.
- الحساسات والقياس: تضخيم الإشارات الضعيفة، ADC/DAC، تكييف الإشارة.
- الاتصالات: UART/SPI/I2C/CAN/RS-485 وواجهات RF عندما تتوفر نماذجها وقواعدها.
- الأنظمة المضمنة: MCU وواجهات البرمجة والذاكرة وإعادة الضبط والساعة والطاقة.
- الدارات المختلطة: Analog/Digital وواجهات المستوى والحماية وEMI/EMC.
- الكهرومغناطيسية: المحولات والملفات والاقتران والهوائيات ضمن أدوات تحليل مناسبة.
- دوائر السلامة والتحكم الصناعي، مع قواعد خاصة بالجهود الخطرة والعزل.

## ما نُفّذ في هذه المرحلة
- Prototype سابق محدود للمقاومة والمكثف والمحث ومصدر الجهد ثنائي الطرف.
- أضيفت مكتبة أولية متعددة الأرجل في schema v2 تشمل عائلات عناصر سلبية وشبه موصلة ومضخمات ومقارنات ومؤقت 555 ومنطق وقلاب ومحولات وموصلات ومفاتيح ونقاط اختبار.\n- أضيف مصدّر KiCad أولي ينشئ ملف `.kicad_sch` قابل للتحرير من النموذج الموحد، مع أرقام الأرجل وتسميات الشبكات. لا يزال يحتاج تحققاً فعلياً بواسطة KiCad CLI وتحسين رموز الأجهزة المتخصصة.
- كل عنصر يربط وظائفه المنطقية بأسماء الشبكات، ويحتاج خريطة أرقام أرجل الحزمة صراحة؛ لا تُفترض أرقام أرجل IC عامة.
- العناصر التي تحتاج نموذج محاكاة تتطلب model_id، لكن وجود هذا المعرّف لا يعني أن ملف النموذج قد تحقق منه أو أصبح صالحاً للمحاكاة.
- تم تمرير التحقق من schema v2 عبر بوابة الأدوات الآمنة بموافقة بشرية.
- مصدّر KiCad موجود كـPrototype ولم يُتحقق من فتحه/تصديره عبر KiCad CLI بعد؛ محرك ERC الشامل ومحاكاة SPICE الكاملة وفحص PCB لم تُنفذ بعد، لذلك لا شيء Build-Ready.

## سياسة نماذج المحاكاة
- الأفضلية لمحرك ngspice المفتوح المصدر مع واجهة واضحة، وتشغيل محلي قابل للتكرار.
- يدعم ngspice عدة تحليلات كهربائية، لكن نوع التحليل الممكن يعتمد على نوع النموذج والمكونات المستخدمة.
- KiCad يربط محرر المخططات بمحرك ngspice، ويقبل نماذج SPICE الخارجية وIBIS لبعض حالات مداخل/مخارج الأجهزة.
- ملفات النماذج الخارجية يجب أن تكون من مصادر موثوقة، نصية وغير مشفرة عند الحاجة، مع تدقيقها قبل تمريرها للمحرك.
- النموذج المثالي لا يساوي نموذج قطعة تجارية بعينها. لا تُستخدم قيم نموذجية بدلاً من بيانات الشركة إلا إذا وُسمت بوضوح كافتراض.
- نتائج المحاكاة الفيزيائية ذات النماذج المناسبة دليل تنبؤي قوي ضمن مجال النموذج؛ وترتفع دقتها بإضافة التفاوتات والطفيليات والحرارة والتوصيلات والحماية.

## بوابات الجودة قبل اعتماد أي تصميم
1. اكتمال متطلبات المستخدم وعدم اختراع القيم الغائبة.
2. تطابق كل رقم رجل مع datasheet والحزمة الفعلية.
3. تطابق المخطط وnetlist وBOM مع نموذج الدارة الموحد.
4. اجتياز ERC وقيود الجهد والتيار والقدرة والحرارة والقطبية والعزل.
5. نجاح التحليلات المناسبة مع توثيق النموذج ومجال الصلاحية.
6. اجتياز اختبارات مرجعية مستقلة وتحليل أسوأ حالة عند الحاجة.
7. مراجعة بشرية نهائية قبل وسم التصميم Build-Ready أو إعطاء تعليمات تنفيذ مادي.

## ترتيب التنفيذ
A. تثبيت نموذج الدارة متعدد الأرجل ومكتبة المكونات ومصادر pinout.
B. توليد KiCad schematic أصلي والتحقق منه بأداة KiCad CLI.
C. بناء ERC كهربائي متدرج واختبارات قصيرة/تعارض مخارج/أرجل عائمة/طاقة.
D. توليد netlist متوافق مع SPICE وربط ngspice وتشغيل تحليلات DC/AC/Transient.
E. نماذج أشباه الموصلات وICs وملفات الشركات مع تدقيقها.
F. التفاوتات والحرارة والطفيليات والحماية وMonte Carlo.
G. BOM احترافي وبدائل ومصادر، ثم PCB/DRC/تصنيع.
H. واجهة المستخدم لعرض المخطط والنتائج والتقارير وتنزيل المشروع.

## حالة الاعتماد
- Prototype: المكتبة متعددة الأرجل والتحقق البنيوي مضافان.
- Validated: لا يُعلن قبل اجتياز CI وفحوص مستقلة لكل مكوّن/مخرج.
- Build-Ready: غير متاح بعد؛ يتطلب KiCad أصلياً وERC والمحاكاة وBOM وبيانات موثقة ومراجعة هندسية.
