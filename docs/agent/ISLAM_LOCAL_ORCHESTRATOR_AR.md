# منسّق المدير المساعد المحلي — ISLAM

## ما الذي أُضيف؟

أضيف `tools/islam_agent/orchestrator.py` لربط طابور المهام بعميل Ollama المحلي وطبقة الاقتراح الآمن.

في كل تشغيل:
1. يقرأ ذاكرة المشروع ويتحقق من بنيتها.
2. يستأنف أول مهمة `in_progress`، وإلا يختار أول مهمة `pending`.
3. يرسل بيانات المهمة المحدودة إلى `LocalAgentWorkflow`.
4. يتحقق مسار العمل من الاقتراح، ثم يعيد المنسّق نفسه التحقق بصورة مستقلة قبل الحفظ: مخطط النتيجة الدقيق، هوية المهمة، قائمة السماح الثابتة، موافقة الإنسان، اسم النموذج وحدود الحجم.
5. يحفظ اقتراحاً واحداً في `artifacts/agent/pending_proposal.json` بانتظار المراجعة البشرية. لا يقبل ملف اقتراح أكبر من 16 KiB ولا يستبدل اقتراحاً سابقاً.

## فحص Ollama قبل التوليد

أضيف `tools/islam_agent/ollama_preflight.py` لفحص وجود خدمة Ollama محلياً، والتحقق من وجود اسم النموذج المطلوب بالضبط عبر `/api/tags` قبل إرسال أي طلب توليد. لا يقبل الفاحص عنواناً بعيداً، ولا يتبع التحويلات، ويعطل البروكسي، ويضع حدوداً للمهلة وحجم الرد. لا يولّد نصاً ولا ينفذ أدوات.

شغّله من جذر المستودع:

```bash
python3 tools/islam_agent/ollama_preflight.py --model <local-model-name>
```

رمز الخروج 0 يعني أن النموذج موجود، و2 يعني أن الخدمة تعمل لكن النموذج غير مثبت، و1 يعني تعذر الفحص أو وجود رد غير صالح.

## التشغيل

من جذر المستودع، وبعد تثبيت Ollama محلياً وتنزيل نموذج مناسب:

```bash
python3 tools/islam_agent/orchestrator.py --model <local-model-name>
```

يمكن تحديد مسارات بديلة للاختبار أو التشغيل:

```bash
python3 tools/islam_agent/orchestrator.py --model <local-model-name> --memory docs/agent/agent_memory.json --proposal artifacts/agent/pending_proposal.json
```

فحص preflight أداة مستقلة حالياً ولا يثبت أن Ollama يعمل على جهاز المستخدم. لا يفترض المنسّق أن Ollama موجود؛ إذا تعذر الاتصال المحلي، يعرض خطأ ولا ينشئ اقتراحاً مزيفاً. اختبارات preflight تستخدم خادم HTTP محلياً وهمياً داخل الاختبار ولا تمثل اتصالاً بنموذج حقيقي.

## حدود الأمان

- المنسّق لا ينفذ خطوات الاقتراح.
- لا يغيّر ذاكرة المشروع ولا حالات المهام.
- لا يكتب إلى ملفات المصدر ولا يتصل بـGitHub.
- لا يستبدل اقتراحاً معلقاً موجوداً؛ يجب حفظه ومراجعته قبل دورة اقتراح جديدة.
- كل اقتراح يبقى `awaiting_human_approval=true` و`executed=false`.
- التنفيذ ما زال منفصلاً ويتطلب موافقة بشرية صريحة عبر `LocalAgentWorkflow.approve_and_execute`.
- اقتراحات النموذج لا تستطيع توسيع قائمة المسارات أو الاختبارات المسموح بها؛ يجري التحقق منها مرة أخرى عند بوابة المنسّق قبل الحفظ.

## ما لم يُثبت بعد

نجاح اختبارات CI لا يعني أن Ollama يعمل على جهاز المستخدم. يجب اختبار اتصال Ollama وتنزيل النموذج على جهاز محلي فعلي قبل اعتبار مسار التوليد العملي متاحاً. كما أن هذا المنسّق ينفذ دورة اقتراح واحدة عند تشغيله؛ لا يعمل تلقائياً بعد إغلاق البرنامج أو الجهاز.

## مراجعة الاقتراح والموافقة قبل التنفيذ

بعد إنشاء اقتراح معلّق، شغّل أداة المراجعة محلياً:

```bash
python3 tools/islam_agent/review_pending.py
```

تعرض الأداة المهمة والملخص والخطوات والادعاءات المطلوب التحقق منها. لا تنفذ شيئاً إلا إذا كتب المشغّل العبارة العربية المعروضة حرفياً:
`أوافق على تنفيذ الاقتراح <task_id>`

أي إدخال مختلف يرفض التنفيذ. يعاد التحقق من بنية السجل وهوية المهمة وقائمة السماح قبل التنفيذ. تحفظ نقاط التوقف في مجلد مراجعة محلي مشتق من بصمة الخطة، حتى يمكن استئناف الخطوات غير المكتملة مع نفس الخطة دون إعادة الخطوات المنجزة. لا تمنح هذه الأداة النموذج صلاحية الموافقة، ولا تعمل من تلقاء نفسها.

اختبارات بوابة المراجعة مضافة إلى التدقيق الثابت. هذا مسار موافقة من طرفية محلية؛ لم يُختبر بعد على جهاز المستخدم أو مع نموذج Ollama حقيقي.
