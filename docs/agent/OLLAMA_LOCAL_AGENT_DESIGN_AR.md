# تصميم العقل المحلي لوكيل إسلام — Ollama

تاريخ التصميم: 2026-11-19
الحالة: مواصفة تنفيذية أولية؛ لم يُربط نموذج فعلي ولم تُنفذ دورة مستقلة بعد.

## 1. الهدف وحدود المجانية

تشغيل نموذج لغوي محلي على حاسوب المستخدم عبر Ollama، دون API مدفوع أو اشتراك أو خادم ذكاء اصطناعي مستضاف. Ollama هو مشغل النموذج المحلي؛ النموذج نفسه يجب أن يكون متاحاً للتنزيل وفق ترخيص يسمح بالاستخدام المقصود، ويجب مراجعة ترخيص كل نموذج قبل اختياره.

لا يعني وصف «مجاني» انعدام التكلفة المادية: يلزم جهاز وموارد كهرباء وذاكرة وتخزين واتصال أولي لتنزيل النموذج. لا نعتمد على runner مدفوع أو خدمة خارجية مدفوعة.

## 2. فصل المسؤوليات

يتكون الوكيل من خمس طبقات منفصلة:

1. **Orchestrator — المنسق الحتمي:** يقرأ المهمة الحالية، يتحقق من حالتها، يحدد المرحلة، ويقرر إن كان مسموحاً بالانتقال.
2. **Local Model Client — عميل Ollama:** يرسل سياقاً محدوداً إلى عنوان محلي فقط، ويستقبل اقتراحاً منظماً. لا يملك أدوات نظام أو GitHub.
3. **Policy Gate — بوابة السياسة:** تتحقق من أن اقتراح النموذج يقع ضمن مخطط JSON معروف، وأن المهمة والملفات والأوامر ضمن قائمة سماح صريحة.
4. **Tool Runner — منفذ الأدوات:** يشغل فقط أوامر محددة مسبقاً مثل اختبارات الوحدة وفحوصات التنسيق. لا ينفذ نص shell حرّاً من النموذج.
5. **Evidence & Checkpoint — سجل الأدلة ونقطة الاستئناف:** يحفظ المهمة والمرحلة والأمر والنتيجة ورمز الخروج وcommit المرجعي ووقت التشغيل.

لا يجوز دمج هذه الطبقات في حلقة واحدة تمنح النموذج وصولاً عاماً إلى النظام.

## 3. الاتصال المحلي

- العنوان الافتراضي: `http://127.0.0.1:11434` فقط.
- الواجهة الأولى: `POST /api/chat` مع `stream: false` لتبسيط التحقق والتسجيل.
- اسم النموذج يحدد من إعداد محلي صريح؛ لا ينزّل البرنامج نموذجاً تلقائياً ولا يختار نموذجاً غير معروف.
- مهلة اتصال وقراءة محددة؛ لا انتظار غير محدود.
- حجم سياق ومخرجات محدودان لتجنب استهلاك الذاكرة بلا ضابط.
- لا يرسل العميل أسرار GitHub أو مفاتيح أو ملفات بيئة أو بيانات شخصية إلى النموذج.
- لا يسمح بإعداد عنوان شبكة بعيد في النسخة الأولى؛ الاتصال المحلي فقط.
- إذا لم يكن Ollama متاحاً، يتوقف مسار الذكاء اللغوي برسالة واضحة، وتظل الفحوصات الحتمية متاحة.

## 4. صيغة الاقتراح

يطلب المنسق من النموذج إرجاع JSON فقط وفق مخطط صغير، مثل:

```json
{
  "task_id": "agent-003",
  "summary_ar": "اقتراح تصميم عميل Ollama المحلي",
  "steps": [
    {
      "kind": "inspect",
      "target": "docs/agent/OLLAMA_LOCAL_AGENT_DESIGN_AR.md"
    },
    {
      "kind": "run_test",
      "target": "agent_unit_tests"
    }
  ],
  "needs_human_approval": true,
  "claims_to_verify": []
}
```

هذا مثال توضيحي للمخطط، وليس أمراً تنفيذياً. يجب التحقق من JSON والحقول والأنواع والقيم المسموحة، ورفض أي حقل إضافي أو أمر غير معروف. لا ينفذ البرنامج أي نص حر يعيده النموذج.

## 5. قائمة الأدوات المسموحة في النسخة الأولى

مسموح:
- قراءة ملفات محددة من مساحة العمل.
- عرض حالة طابور المهام وسجل الأدلة.
- تشغيل مجموعات اختبارات مسماة مسبقاً.
- تشغيل فحوصات Python ساكنة مسماة مسبقاً.
- إنشاء تقرير داخل مجلد تقارير مخصص.

غير مسموح:
- shell عام أو أوامر يكتبها النموذج.
- تنزيل برامج أو حزم أو نماذج دون موافقة المستخدم.
- الوصول إلى الشبكة العامة أو تغيير عنوان Ollama إلى مضيف بعيد.
- قراءة ملفات الأسرار أو متغيرات البيئة الحساسة.
- تعديل ملفات التصميم الكهربائي أو قيم الملف أو مواصفات الجهاز.
- commit أو push أو فتح PR آلياً في النسخة الأولى.
- دمج PR أو تعديل main في أي مرحلة مستقلة.

## 6. دورة العمل المحدودة

كل دورة تنفذ مهمة واحدة فقط:

1. تحميل الذاكرة والتحقق من سلامة المخطط.
2. اختيار أول مهمة pending وفق الأولوية.
3. إنشاء checkpoint قبل بدء التنفيذ.
4. جمع أقل سياق لازم من الملفات المسموحة.
5. طلب خطة JSON من النموذج المحلي.
6. التحقق من الخطة عبر Policy Gate.
7. تشغيل الأدوات المسموحة فقط.
8. حفظ المخرجات ورموز الخروج كما هي.
9. تحديث المهمة إلى completed فقط إذا تحققت شروط القبول؛ وإلا تبقى in_progress أو تصبح blocked مع السبب.
10. حفظ checkpoint نهائي وإنهاء الدورة.

لا تبدأ دورة ثانية تلقائياً في الإصدار الأول. بعد إثبات دورة واحدة، يمكن السماح بعدد أقصى صغير من الدورات في جلسة واحدة مع حد زمني وحد استهلاك وإيقاف فوري.

## 7. الاستئناف والتعامل مع الانقطاع

يحفظ checkpoint بصيغة JSON مستقلة تتضمن:
- schema_version
- run_id
- task_id
- phase
- started_at وupdated_at
- source_commit
- last_tool
- last_exit_code
- status
- failure_reason

عند إعادة التشغيل:
- إذا كان checkpoint مكتملًا، يبدأ من مهمة جديدة.
- إذا كان قيد التنفيذ، يعيد التحقق من آخر خطوة قبل استئنافها.
- لا يعيد تنفيذ خطوة غير آمنة أو غير قابلة للتكرار تلقائياً.
- لا يضع المهمة completed بسبب توقف البرنامج أو انتهاء المهلة.
- يكتب الملفات ذرياً، ويمنع تشغيل نسختين متزامنتين باستخدام قفل محلي.

## 8. سجل الأدلة

كل نتيجة تسجل:
- الوقت UTC
- commit أو نسخة المصدر
- المهمة والمرحلة
- اسم الأداة ومعاملاتها المعتمدة
- exit code
- مقتطف مخرجات محدود مع إزالة الأسرار
- هل نفذت فعلياً أم تخطيت أم تعذر تشغيلها
- حدود الاستنتاج

يجب الفصل بين: لم يُشغّل، فشل، نجح اختبار برمجي، نجحت محاكاة، وقياس ميداني. لا يحوّل النموذج حالة «لم يُشغّل» إلى نجاح.

## 9. مراحل التنفيذ والقبول

### OLLAMA-01 — عميل محلي فقط
عميل Python قياسي يتصل بـ127.0.0.1، بمهلة، واستجابة غير متدفقة، ومعالجة واضحة للأخطاء. اختبارات باستخدام خادم HTTP وهمي محلي؛ لا تحتاج تنزيل نموذج.

### OLLAMA-02 — التحقق من الاقتراحات
مخطط JSON صارم واختبارات ترفض النص غير الصحيح والحقول الإضافية وأنواع الأدوات غير المسموحة.

### OLLAMA-03 — تشغيل تجريبي للقراءة والتقرير
النموذج يقترح خطة، والمنسق يسمح بالقراءة وإنشاء تقرير فقط. لا تعديل للمصدر ولا تنفيذ shell حر.

### OLLAMA-04 — أدوات الاختبار المحددة
السماح بمجموعات اختبارات مسماة ومثبتة مسبقاً، وتسجيل exit codes. لا يسمح للنموذج بإنشاء أمر جديد.

### OLLAMA-05 — Checkpoint واستئناف
اختبارات توقف وانقطاع وفشل واستئناف، ومنع إكمال المهمة دون أدلة.

### OLLAMA-06 — دورة متعددة محدودة
عدة مهام متتابعة بحد أقصى واضح للوقت والمهام، مع إيقاف يدوي، وتقرير ختامي. لا تشغيل 24/7 مضمون.

### OLLAMA-07 — اقتراح تغييرات عبر فرع
مرحلة منفصلة لاحقة: تغييرات في فرع وكيل وDraft PR فقط، بعد موافقة صريحة على تفعيل صلاحية الكتابة. لا دمج تلقائي.

## 10. شروط الجاهزية

لا نعلن أن العقل المحلي جاهز قبل:
- نجاح اختبارات عميل Ollama ومخطط JSON.
- رفض جميع الأوامر غير المسموحة في اختبارات سلبية.
- إثبات أن غياب Ollama لا يعطل الفحوصات الحتمية.
- استئناف صحيح بعد انقطاع تجريبي.
- إكمال ثلاث دورات متتالية موثقة دون إكمال مهمة بلا دليل.
- عدم الوصول إلى أسرار أو شبكة خارجية أو main.
- مراجعة المستخدم للتقرير النهائي.

## 11. القرار الحالي

نبدأ بـ OLLAMA-01 كعميل اتصال محلي مع اختبارات خادم وهمي، دون تشغيل نموذج أو تنزيله تلقائياً. لا نضيف أي صلاحيات كتابة للمستودع أو تعديل ملفات الجهاز في هذه المرحلة.
