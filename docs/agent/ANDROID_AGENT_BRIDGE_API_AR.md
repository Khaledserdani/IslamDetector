# عقد ربط تطبيق ISLAM FREE AGENT بمحرك الوكيل المحلي

الحالة: مواصفة واجهة؛ لا يوجد خادم HTTP أو اتصال Android منفذ بعد.
الإصدار: 0.1
التاريخ: 2026-11-20

## 1. القرار المعماري

تطبيق Android الحالي هو واجهة وإدارة محلية للمهام فقط. محرك الوكيل الموجود في `tools/islam_agent/` يعمل ببايثون، وعميل Ollama فيه مقيد بعنوان loopback على الحاسوب الذي يشغل Ollama. لذلك لا يستطيع تطبيق الهاتف الاتصال بـ`127.0.0.1:11434` على حاسوب آخر؛ هذا العنوان يشير إلى الهاتف نفسه.

المسار المقترح عند وجود حاسوب موثوق على الشبكة المحلية:

`Android app ⇄ HTTPS + pairing ⇄ Python Agent Bridge ⇄ Local Orchestrator ⇄ Ollama on 127.0.0.1`

- لا يتصل Android بـOllama مباشرة.
- لا توضع GitHub tokens أو مفاتيح Ollama أو أسرار المستودع داخل APK.
- يبقى Ollama مربوطاً بـ`127.0.0.1:11434` على الحاسوب المضيف.
- لا يُفتح منفذ Ollama على الشبكة.
- لا ينفذ النموذج أي أمر حر؛ يمر كل اقتراح عبر Policy Gate.
- تبقى الموافقة البشرية مطلوبة قبل تشغيل أي خطوة.
- وضع عدم الاتصال يظل متاحاً لإدارة المهام المحلية في الهاتف.

## 2. متطلبات الأمان قبل فتح الاتصال

لا يسمح بتفعيل اتصال LAN قبل تنفيذ جميع الشروط التالية:

1. HTTPS فقط مع شهادة موثوقة أو شهادة محلية مثبتة البصمة (certificate pinning) داخل جلسة الاقتران.
2. اقتران يدوي برمز عشوائي أحادي الاستخدام، قصير العمر، يولده المضيف ويعرضه للمستخدم.
3. إصدار رمز جلسة عشوائي بعد الاقتران؛ يخزن في Android Keystore، ولا يكتب في السجلات.
4. صلاحيات منفصلة للقراءة وطلب الاقتراح والموافقة؛ لا تعني جلسة القراءة صلاحية التنفيذ.
5. حد أقصى لحجم الطلبات والردود، ومهلة اتصال، وتحديد معدل الطلبات.
6. ربط خادم Ollama بالـloopback فقط، وعدم قبول endpoint بعيد من الهاتف أو من النموذج.
7. رفض الطلبات غير المعروفة والحقول الزائدة، والتحقق من نوع ومجال كل قيمة.
8. سجل تدقيق لا يحفظ الرموز أو كلمات المرور أو محتوى حساساً.
9. لا يعمل الخادم على الإنترنت العام ولا يفتح منفذاً موجهاً من الراوتر.
10. لا يتم تنفيذ موافقة بمجرد وصول نص من النموذج؛ يجب أن تكون عملية مستقلة صادرة عن واجهة المستخدم بعد عرض الخطة.

إذا لم تتوفر TLS وبصمة الشهادة والاقتران الآمن، يبقى الاتصال معطلاً ولا نستبدله بـHTTP مكشوف على الشبكة.

## 3. قواعد API

- Base path: `/v1`
- Content-Type: `application/json; charset=utf-8`
- كل الردود تحمل `request_id` عشوائياً للتتبع، لا يتضمن أي سر.
- أخطاء موحدة: `{ "error": { "code": "...", "message_ar": "..." }, "request_id": "..." }`
- لا تقبل الواجهة مسارات ملفات أو أوامر shell أو عناوين Ollama من المستخدم.
- معرفات المهام والاقتراحات هي معرفات opaque؛ لا تستخدمها كمسارات ملفات.

## 4. المسارات المقترحة

### GET /v1/health

يعيد حالة الجسر والمحرك، دون إظهار أسرار أو مسارات خاصة:

```json
{
  "api_version": "0.1",
  "bridge": "ready",
  "orchestrator": "available",
  "ollama": "available",
  "model": "model-name",
  "proposal_pending": false
}
```

قيم الحالة المسموحة: `ready`, `unavailable`, `not_configured`. لا يعلن `ollama: available` إلا بعد فحص حقيقي حديث.

### GET /v1/tasks

يعرض قائمة المهام للقراءة فقط: `id`, `title`, `status`, `updated_at`. لا يعرض محتوى ملفات المشروع ولا متغيرات البيئة.

### POST /v1/proposals

يشغل دورة اقتراح واحدة فقط، لا تنفيذ:

```json
{ "task_id": "task-identifier" }
```

يجب أن يطابق المعرف المهمة النشطة. الرد إما `proposal_created` مع `proposal_id` وملخص وخطوات مقيدة، أو خطأ صريح مثل `ollama_unavailable` أو `proposal_already_pending`. لا يقبل endpoint نص prompt أو خطوات يرسلها الهاتف.

### GET /v1/proposals/pending

يعرض الاقتراح المعلق ومعلوماته: `proposal_id`, `task_id`, `summary_ar`, `steps`, `claims_to_verify`, `awaiting_human_approval`, `executed`. يجب أن تكون القيمتان الأخيرتان `true` و`false` على الترتيب قبل الموافقة.

### POST /v1/proposals/{proposal_id}/decision

يقبل قراراً صريحاً واحداً:

```json
{ "decision": "approve", "confirmation_text": "أوافق على تنفيذ الاقتراح task-identifier" }
```

أو `decision: "reject"`. عند الرفض لا تنفذ أي خطوة. عند الموافقة، يعيد الخادم التحقق من بصمة الاقتراح وقائمة السماح وحالة المهمة، ثم يشغل خطوة واحدة في كل مرة عبر منفذ الأدوات الثابت. لا يقبل هذا المسار أوامر أو أهدافاً إضافية من الهاتف. كل خطوة تسجل نتيجتها، ويتوقف التنفيذ عند أول فشل أو تغير في الخطة.

هذا endpoint لا يُنفذ حتى تكتمل مصادقة الجلسة وTLS ومراجعة اختبارات الموافقة وإعادة التشغيل.

## 5. رموز الخطأ الدنيا

| الرمز | المعنى |
|---|---|
| `not_paired` | الهاتف غير مقترن بالمضيف |
| `unauthorized` | رمز الجلسة غير صالح |
| `ollama_unavailable` | Ollama غير متاح محلياً |
| `model_not_installed` | النموذج المحدد غير مثبت |
| `proposal_already_pending` | يوجد اقتراح ينتظر المراجعة |
| `proposal_stale` | تغيرت المهمة أو بصمة الخطة |
| `policy_rejected` | الاقتراح خارج قائمة السماح |
| `approval_required` | لم تصل موافقة بشرية صحيحة |
| `rate_limited` | تجاوز معدل الطلبات |
| `payload_too_large` | تجاوز الطلب الحد الأقصى |

## 6. آلة الحالات

`disconnected → paired → ready → proposal_pending → approved → executing → completed | paused | failed`

- `proposal_pending` لا تعني الموافقة.
- `approved` لا تعني اكتمال التنفيذ.
- `paused` تحفظ نقطة التوقف ولا تعيد تنفيذ الخطوات الناجحة.
- `failed` تتضمن رمز الخطأ والأدلة المتاحة.
- لا يجوز للتطبيق تحويل حالة غير معروفة إلى نجاح.

## 8. الوضع الحالي وما لم يُنجز

- موجود: واجهة Android أولية، وتخزين مهام محلي.
- موجود: وحدات Python للمنسق المحلي وعميل Ollama وبوابة السياسة ونقاط الاستئناف ومراجعة الاقتراح.
- غير موجود: خادم Bridge أو API أو TLS pairing.
- غير موجود: عميل شبكة في تطبيق Android.
- غير مثبت: تشغيل Ollama على حاسوب المستخدم أو دورة اقتراح فعلية على جهازه.
- غير مثبت: APK المدير المساعد؛ GitHub Actions يفشل حالياً قبل إنشاء أي Job، لذلك لم يبدأ بناء Android.

هذا العقد يحدد الحدود المطلوبة قبل كتابة الاتصال. لا يمثل خادماً منفذاً أو اتصالاً عاملاً.
