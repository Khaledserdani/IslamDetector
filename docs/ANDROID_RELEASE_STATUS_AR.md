# حالة تسليم تطبيقي Android — دستور إسلام

**التاريخ:** 2026-11-13  
**النطاق النهائي:** تطبيقان فقط، ولا يوجد تطبيق ثالث.

## التطبيقات
| التطبيق | وحدة Gradle | applicationId | الحالة |
|---|---|---|---|
| ISLAM DETECTOR | `:app` | `com.islamdetector.app` | واجهة اتصال وسجل محلي؛ تكامل الجهاز الحقيقي غير مكتمل |
| ISLAM LAB | `:lab` | `com.islamlab.app` | تطبيق مختبر ومحاكاة/إدخال بيانات؛ ليس بديلاً عن التحقق الفيزيائي |

## ما تم تنفيذه
- تصحيح خطة التنفيذ الرسمية لإلغاء أي إشارة إلى تطبيق Android ثالث.
- إضافة دعم توقيع Release بمفتاح keystore ثابت يمرر عبر بيئة البناء، إلى وحدتي Android.
- استبدال مسار Release القديم الذي كان يخص ISLAM LAB وحده بمسار موحد يبني APK موقّعين للتطبيقين.
- مسار Release يتحقق من معرف الحزمة، وصحة توقيع APK، وتطابق بصمة شهادة التوقيع بين التطبيقين، ثم يحسب SHA-256.
- لا يستخدم مسار Release مفتاح Debug المؤقت كهوية نهائية.

## ما يمنع التسليم النهائي الآن
1. لم تُضف أسرار توقيع المشروع إلى إعدادات GitHub Actions. المسار ينتظر الأسرار التالية:
   - `ANDROID_KEYSTORE_BASE64`
   - `ANDROID_STORE_PASSWORD`
   - `ANDROID_KEY_ALIAS`
   - `ANDROID_KEY_PASSWORD`
2. لم يتم التحقق بعد من تثبيت التطبيقين وتشغيلهما وتحديثهما على هاتف Android فعلي.
3. تطبيق ISLAM DETECTOR ينتظر Firmware فعلياً للـESP32-S3 يطبق عقد الاتصال المتفق عليه؛ الواجهة وحدها لا تثبت تشغيل الجهاز.
4. يجب مواصلة اختبار وظائف ISLAM LAB على بيانات علمية موثقة، مع إبقاء البيانات الاصطناعية والمحاكاة والقياسات الفعلية منفصلة.

## معيار إعلان التسليم
لا يعلن أي تطبيق «نهائياً» قبل وجود APK Release موقع بالمفتاح الثابت نفسه، والتحقق من بصمة الشهادة وSHA-256، واختبار التثبيت والتشغيل والتحديث. ولا تُعرض Artifacts Debug على أنها نسخ نهائية.

## حماية مفتاح التوقيع
لا يوضع ملف keystore أو كلمات مروره في المستودع أو في سجل Git. يحتفظ مالك المشروع بنسخة احتياطية آمنة من keystore وكلمات المرور؛ فقدان المفتاح قد يمنع تحديث التطبيق المثبت سابقاً.
