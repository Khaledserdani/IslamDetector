# المعمارية الكهربائية الوظيفية لجهاز إسلام PI
**المراجعة:** A — مخطط كتل وظيفي قبل اختيار العناصر والقيم.  
**النطاق:** الجهاز وحده؛ مستقل عن تطبيق Android وISLAM LAB في مرحلة التطوير والاختبار.

## 1. حدود الطاقة والإشارة
يُقسم الجهاز إلى نطاقين للطاقة:
- **نطاق المتحكم:** Power Bank 5V ثم تنظيم الجهد المناسب للوحة ESP32-S3-N16R8. هذا النطاق يغذي المتحكم ودوائر التوقيت والاتصال والقياس منخفضة الطاقة حسب ميزانية الاستهلاك.
- **نطاق نبضة الملف:** مصدر منفصل للـ TX، مع حماية وفصل مناسبين وقياس تيار النبضة. لا يُغذى الملف من USB أو الهاتف، ولا يُفترض جهد المصدر أو تياره قبل قياس L وتحديد زمن النبضة والتيار المستهدف.

تُحدد نقاط الأرضي والربط بين النطاقين في المخطط التفصيلي بعد دراسة مسارات تيار النبضة والقياس والضوضاء؛ لا يُفترض أن ربط الأرضي في نقطة عشوائية آمن أو قليل الضوضاء.

## 2. مخطط الكتل — مسار الإرسال
```text
مصدر طاقة TX مستقل
       |
حماية دخل + فصل/تمكين
       |
مكثف/خزان طاقة محسوب
       |
مرحلة تبديل قدرة (MOSFET + Driver)
       |
ملف TX في DD32
       |
قياس تيار النبضة + التقاط الجهد العابر
       |
عودة طاقة/امتصاص نبضة مصمم على أساس القياس
```

### واجهات التحكم
- ESP32-S3 يرسل أمر التوقيت إلى Driver، ولا يقود بوابة MOSFET مباشرة.
- يحدد Firmware عرض النبضة ومعدل التكرار ضمن حدود أمان مقفلة في البداية.
- تُقاس نبضة البوابة وDrain/Collector وتيار الملف بأدوات مناسبة قبل رفع الطاقة.
- يجب أن يكون فصل TX ممكناً عند زيادة التيار أو ارتفاع الحرارة أو خلل التوقيت.

## 3. مخطط الكتل — مسار الاستقبال
```text
ملف RX
  |
حماية أولية محددة من قياس الجهد العابر
  |
تحديد/تخميد الرنين عند الحاجة وبقيم محسوبة
  |
مرحلة استعادة/تهدئة بعد نبضة TX
  |
مضخم منخفض الضوضاء أو واجهة استقبال مناسبة
  |
ترشيح + إزاحة/تهيئة مجال الإشارة عند الحاجة
  |
ADC / أخذ عينات متزامن
  |
ESP32-S3: عينات خام + طوابع زمنية + حالة الجودة
```

لا توضع مقاومة أو TVS أو دايود clamp عشوائياً على RX: سعة عناصر الحماية وتسريبها قد يغيران حساسية الملف. يختار ترتيب الحماية بعد قياس التسريب والجهد العابر وزمن الاستعادة.

## 4. التوقيت الرقمي
دورة PI الوظيفية:
1. تهيئة العتاد والتحقق من حالة الحماية.
2. إطلاق نبضة TX لمدة محددة.
3. إطفاء مرحلة القدرة وتسجيل لحظة الإطفاء.
4. الانتظار حتى دخول الإشارة في مجال الاستقبال الآمن.
5. أخذ عدة عينات RX في نوافذ زمنية محددة بالنسبة إلى لحظة إطفاء TX.
6. حفظ العينات الخام والوقت والإعدادات دون فقدها بسبب الترشيح أو التصنيف.
7. حساب مؤشرات أولية ثم بدء الدورة التالية.

يجب أن تكون نافذة RX مرتبطة بحدث الإطفاء الفعلي أو توقيت مضبوط قابل للقياس، لا بتأخير برمجي غير حتمي داخل حلقة Wi-Fi. تُفصل مهمة القياس الحتمية عن مهام الشبكة والواجهة.

## 5. جدول الواجهات بين الكتل
| الواجهة | الإشارات/المعلومات | ما يجب قياسه قبل اعتمادها |
|---|---|---|
| مصدر TX ← Driver | جهد التغذية، تيار الذروة، التموج | هبوط الجهد، التيار، الحرارة |
| ESP32 → Driver | أمر تشغيل/إيقاف، عرض النبضة | مستوى المنطق، زمن الحافة، حالة الإطفاء |
| Driver → TX | تيار الملف والجهد العابر | شكل النبضة، الطاقة، overshoot |
| RX → الحماية | إشارة مستحثة + تسريب TX | أقصى جهد، قطبية، زمن التعافي |
| التهيئة → ADC | إشارة ضمن مجال الدخل | الضوضاء، الكسب، عرض الحزمة، التشبع |
| ADC → Firmware | عينات وقيم خام | معدل العينة، الدقة، jitter |
| Firmware → سجل البيانات | إعدادات الدورة والعينات | اكتمال السجل والطابع الزمني |

## 6. متطلبات الاختبار المرحلي
- **اختبار المتحكم منفرداً:** توقيت خرج منطقي على حمل آمن، دون Driver أو ملف.
- **اختبار Driver منفرداً:** حمل اختباري مناسب ومصدر محدود التيار، مع قياس بوابة التبديل والحرارة.
- **اختبار TX منخفض الطاقة:** بعد توصيف الملف، وبمصدر نبضة محدود الطاقة، مع قياس التيار والجهد العابر.
- **اختبار RX منفرداً:** حقن إشارة مرجعية صغيرة ومعروفة وقياس الكسب والضوضاء والتشبع.
- **اختبار TX/RX معاً:** قياس التسريب وزمن الاستعادة وتحديد أول نافذة عينة صالحة.
- **اختبار التوقيت:** مقارنة لحظات TX وعينات RX على أداة قياس مستقلة، مع Wi-Fi مشغولاً ومطفأً.

لا ينتقل الاختبار إلى طاقة أعلى إلا بعد تسجيل نتيجة المرحلة السابقة وسلامة الحماية.

## 7. ما لم يُحسم عمداً
هذه الوثيقة لا تعتمد بعد:
- جهد أو تيار مصدر TX.
- رقم MOSFET أو Driver أو TVS أو قيمة مقاومة بوابة/تخميد.
- نوع ADC النهائي أو تردد أخذ العينات.
- زمن blanking أو عرض النبضة أو تردد تكرار PI.
- نقطة الربط بين أرضي القدرة وأرضي القياس.

تُستخرج هذه القيم من قياسات ملف DD32 وميزانية الطاقة والجهد العابر والاستعادة، لا من قائمة قطع عامة.

## 8. مخرجات التصميم التفصيلي التالية
1. رسم هندسي DD32 محدد الأبعاد والمواضع.
2. جدول قياسات DCR وL والاقتران.
3. حساب طاقة الملف والتيار وزمن التفريغ.
4. مخطط TX التفصيلي مع مسارات الحماية والقياس.
5. مخطط RX التفصيلي مع مجال الدخل وزمن الاستعادة.
6. جدول نقاط اختبار TP وأجهزة القياس المطلوبة.
