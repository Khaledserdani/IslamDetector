# دستور التنفيذ الواقعي — الجهاز والتطبيقان النهائيان
**التاريخ:** 2026-11-13  
**الحالة:** خطة تنفيذ معتمدة؛ البنود غير المقاسة لا تُعامل كإنجاز.

## الهدف النهائي
تسليم تطبيقين مستقلين فقط بصيغة APK نهائية قابلة للتثبيت والتحديث، إضافة إلى جهاز PI حقيقي مكتمل ومختبر:
1. ISLAM DETECTOR — تطبيق Android لتشغيل جهاز الكشف الحقيقي.
2. ISLAM LAB — تطبيق Android مستقل للمختبر العلمي والمحاكاة والقياسات والتقارير.
3. جهاز ISLAM DETECTOR الفيزيائي — ملف DD32 ودوائر TX/RX وESP32-S3 والهيكل.
لا يوجد تطبيق Android ثالث، ولا يجوز إنشاء وحدة أو حزمة ثالثة.

## حالة البناء البرمجي التي يجب عدم خلطها
- تصحيح رسمي: المنتج البرمجي النهائي يتكون من تطبيقين Android فقط، ISLAM DETECTOR وISLAM LAB. أي ذكر سابق لتطبيق Android ثالث خطأ ملغى.
- الفرع الحالي: `feature/islam-lab-foundation`.
- آخر نقطة محفوظة عند إعداد هذه الوثيقة: `1062969f36f52ae27528d558cebd02dd0229026b`.
- وحدة Gradle `:app` تبني حزمة `com.islamdetector.app`.
- وحدة Gradle `:lab` تبني حزمة `com.islamlab.app`.
- هاتان هما وحدتا Android النهائيتان المعتمدتان؛ لا تنشأ وحدة Android ثالثة.
- Workflow الحالي يبني APKs من نوع Debug ويجري اختبارات وفحص الحزم. هذه ليست إصدارات نهائية.
- Workflow المرشح لـISLAM LAB يستخدم توقيع Debug مؤقتاً؛ لا يصلح لهوية تحديث دائمة. الإصدار النهائي يتطلب keystore ثابتاً يملكه صاحب المشروع، وتوقيعاً متحققاً منه.
- لا يُدمج PR #8 ولا تُعدّل `main` دون موافقة صريحة.

## المواصفات الثابتة لملف DD32
- الامتداد الخارجي الاسمي: 320 mm؛ لا يُعامل كقطر جناح دائري.
- TX: نحاس مينا 0.60 mm، طول 25 m، 20 لفة، محاثة مستهدفة 300–400 µH.
- RX: نحاس مينا 0.40 mm، طول 35 m، 30 لفة، محاثة مستهدفة 650–900 µH.
- المقاومة النظرية عند 20°C: TX ≈ 1.52 Ω وRX ≈ 4.80 Ω. هذه قيم حسابية، وليست قياسات الملف.
- لا تغيير في قطر السلك أو الطول أو عدد اللفات دون دليل وقرار موثق.
- أبعاد عرض القالب، حدود جناحي D، التداخل، الارتفاع، والفصل الرأسي ومخارج الأسلاك تُقاس على القالب الفعلي؛ لا تُخترع قيم لها.

## شراء وتصنيع الملف — ترتيب لا يقفز على القياس
### قبل الشراء
- جرد السلك الموجود فعلياً والتحقق من قطر النحاس المعدني لا القطر الخارجي مع المينا، وقياس طول كل بكرة. لا يُشترى سلك مكرر قبل مطابقة الموجود مع مواصفة TX وRX أعلاه.
- لا يُطلب قالب نهائي من ورشة قبل رسم الجناحين وقياس عرضهما ومنطقة التداخل على مخطط بالحجم الطبيعي.
- توثيق مادة القالب والعازل وارتفاع الحزم ومكان خروج السلكين وطريقة تخفيف الشد.

### أدوات القياس اللازمة لاعتماد الملف
- ملتيميتر جيد مع تعويض مقاومة المجسات، ويفضل قياس Kelvin للمقاومة المنخفضة.
- جهاز LCR يقيس L وRseries وQ عند 100 Hz و1 kHz أو يسجل تردد الاختبار الفعلي.
- ميزان حرارة تلامسي لتسجيل درجة حرارة النحاس.
- راسم إشارة مع وسيلة قياس تفاضلية/معزولة مناسبة عند اختبار الاستجابة.
- مصدر نبض/إشارة محدود الطاقة مع مقاومة سلسلة وحد تيار معلوم لاختبار الاقتران منخفض الطاقة.
- لا يُستخدم مشبك أرضي راسم مؤرض على عقدة عائمة أو عالية الجهد.

### خطوات التصنيع والقبول
1. إعداد رسم القالب 1:1 مع الامتداد الخارجي 320 mm وتحديد TX وRX والتداخل ومخارج الأسلاك.
2. لف TX وRX كل واحد مستقلاً، مع عدّ اللفات وتسجيل طول السلك الفعلي واتجاه اللف وطرفي A/B.
3. قياس DCR ثلاث مرات لكل ملف مع درجة الحرارة، ثم قياس L وRseries وQ لكل ملف منفرداً.
4. تثبيت الملفين مؤقتاً على القالب، وقياس الاقتران والتسريب والاستجابة منخفضة الطاقة.
5. إعادة قياس DCR وL بعد التثبيت؛ لا يُغلق القالب نهائياً قبل توثيق النتائج.
6. حفظ ملف القياسات الخام وإصدار الرسم ومواد التصنيع.

## بوابة شراء إلكترونيات TX — مؤجلة حتى قياسات الملف
لا تُعتمد ولا تُشترى كقطع نهائية أرقام MOSFET أو Driver أو TVS أو Fuse أو شنت أو مصدر 12V قبل قياس DCR/L والاقتران وتحديد جهد المصدر وتيار الذروة وعرض النبضة ومسار إطفاء التيار والطاقة والحرارة. لا تُحوّل أي قائمة أجزاء قديمة إلى قائمة شراء نهائية تلقائياً.
بعد القياس يُشتق التصميم من:
- تيار الذروة وعرض النبضة والتكرار.
- طاقة الملف (E=\frac12 LI^2\).
- أقصى جهد Drain والجهد العابر وحرارة عناصر clamp.
- حدود سائق البوابة وMOSFET ومصدر القدرة.
ويُختبر كل جزء تدريجياً بمصدر محدود التيار وحمل/قياس مناسب قبل توصيل ملف البحث.

## بوابة الاستقبال RX
- لا يعتمد مضخم أو ADC أو قيم الحماية النهائية قبل قياس تسريب TX إلى RX وزمن الاستعادة ومستوى الجهد المستحث.
- نموذج OPA365 وميزانية الضوضاء في المختبر نماذج حسابية؛ لا تمثل بعد موجة RX مقاسة من DD32.
- بعد قياس الملف، تُحدد حماية RX، والكسب، وعرض الحزمة، ومعدل أخذ العينات، ونافذة القياس، ثم تُختبر بإشارة مرجعية منخفضة الطاقة.

## Firmware والجهاز
- لا يوجد بعد Firmware نهائي موثق للـESP32-S3 في الفرع الحالي.
- بعد استقرار TX/RX يُنفذ توليد PI وجمع العينات الخام متعدد النوافذ، ثم Wi-Fi AP/WebServer ونقاط الحالة والتحكم.
- يجب أن يستمر التوقيت والقياس عند انقطاع Wi-Fi أو انشغال الهاتف.
- لا تُعرض قيم اصطناعية على أنها قياسات الجهاز.

## التطبيقان النهائيان — شرط التسليم
- ISLAM DETECTOR (`:app` / `com.islamdetector.app`): APK مستقل، اتصال Wi-Fi حقيقي مع ESP32-S3، قراءات الجهاز الخام، المعايرة والسجل والتصدير.
- ISLAM LAB (`:lab` / `com.islamlab.app`): APK مستقل للمختبر، يعرض محركات المختبر والبيانات والاختبارات العلمية، مع فصل واضح بين synthetic وsimulated وmeasured.
- العدد النهائي تطبيقان فقط؛ لا تُنشأ وحدة أو حزمة Android ثالثة.
- كل APK نهائي يجب أن يكون Release موقعاً بمفتاح ثابت مملوك للمشروع، مع versionCode متزايد وبصمة SHA-256 واختبار تثبيت وتحديث على هاتف Android.
- لا تُسلّم Artifacts Debug على أنها نهائية.

## قواعد التنفيذ
- الجهاز والتطبيقات يتقدمان بالتوازي؛ لا نؤخر تصنيع الملف بسبب استكمال البرمجيات ولا نؤخر البرمجيات بسبب الجهاز.
- «واصل» يعني الانتقال إلى الخطوة العملية التالية دون إعادة فتح القرارات المحسومة.
- كل نتيجة غير مقاسة تبقى «قيد الاختبار».
- لا يعلن نجاح التصنيع أو الكشف أو العمق قبل اختبار واقعي موثق.
